光脑方案-局限九-多轮对话状态维持解决方案

一、问题定义

局限名称：多轮对话状态维持

问题描述：当前架构中，多轮对话的话题追踪、指代消解、跨轮推理链维护依赖简单的工作记忆暂存，缺乏系统性的设计。随着对话轮次增加，系统难以准确追踪话题切换、消解“它”“那个”等指代词、维持跨轮推理的连贯性，导致回复与历史语境脱节。

根本原因：对话状态（话题、实体指代、待决问题）分散在工作记忆、海马体等多个组件中，缺乏一个统一的、显式的对话状态跟踪器来集中管理和更新这些信息。

二、设计哲学

1. 对话状态应显式建模。
对话状态不是工作记忆的附属品，而是一个独立的、结构化的一等公民。话题栈、实体指代表、待决问题队列等应作为前额叶的专用子模块显式维护，而非散落在组块中隐式表达。

2. 就近消解，远端回溯。
指代消解优先在当前工作记忆和对话状态中查找。若模糊或未找到，再向海马体发起历史检索。分层消解既保证了效率，又覆盖了跨会话的远距离指代。

3. 状态更新与推理同步。
每轮对话结束后，对话状态跟踪器根据本轮丘脑标签、实体列表、前额叶决策结果同步更新。状态维护不是后台异步任务，而是推理流程的有机组成部分。

4. 与现有模块协同，而非替代。
对话状态跟踪器是对工作记忆、海马体、丘脑已有信息的整合与升华，不是另起炉灶。它从各模块提取关键信息，统一维护，再反哺给调度决策。

5. 智能生命周期管理。
对话状态不应无限累积。通过语义关联自动清理、用户自主删除、定时任务强保留、话题栈观察期等机制，实现状态的动态收敛与精准保留，避免臃肿同时保证关键信息不丢失。

三、对话状态跟踪器架构

3.1 模块定位

对话状态跟踪器（Dialog State Tracker，DST）是前额叶内部的一个专用子模块，与会话生命周期绑定。

属性 说明
位置 前额叶内部
生命周期 与会话绑定，会话结束可选择性持久化
职责 维护话题栈、实体指代表、待决问题队列、用户目标推测
输入 丘脑标签（意图、实体、情感）、工作记忆当前组块、前额叶决策结果
输出 消解后的具体实体、话题切换信号、待决问题提醒

3.2 核心数据结构

```rust
struct DialogState {
    topic_stack: Vec<Topic>,                          // 话题栈
    entity_reference: HashMap<String, Vec<Entity>>,   // 实体指代表
    pending_questions: VecDeque<PendingQuestion>,     // 待决问题队列
    inferred_goal: Option<UserGoal>,                  // 用户目标推测
    last_updated: u64,
}

struct Topic {
    name: String,              // 话题名称
    entities: Vec<String>,     // 该话题下的核心实体
    start_turn: usize,         // 话题开始的轮次
    last_turn: usize,          // 话题最后活跃的轮次
    status: TopicStatus,       // Active / Dormant / Archived
}

struct Entity {
    name: String,              // 实体名称
    entity_type: String,       // 实体类型（人物、工具、概念等）
    mentioned_at: usize,       // 提及轮次
    salience: f32,             // 显著性（随提及次数和时间衰减）
}

struct PendingQuestion {
    id: String,
    question: String,          // 用户原始问题
    intent: Intent,            // 问题意图
    raised_at: usize,          // 提出轮次
    status: QuestionStatus,    // Pending / PartiallyAnswered / Resolved / AwaitingCleanup
    semantic_trace: Vec<f32>,  // 最近100轮的语义关联度记录
    is_timed: bool,            // 是否定时任务
    trigger_time: Option<u64>, // 定时触发时间戳
    reminded_count: u32,       // 已提醒次数
}
```

四、核心机制

4.1 话题追踪

话题切换检测：每轮对话后，计算当前轮与话题栈栈顶的语义相似度（使用丘脑输出的话题向量）。若相似度低于阈值（建议0.3），判定为话题漂移。

话题栈更新：

· 若为新话题：将新话题压入栈顶。
· 若延续当前话题：更新栈顶话题的last_turn和实体列表。
· 若用户返回旧话题：从栈中弹出直到匹配的话题，或检索历史话题栈。

话题栈持久化与恢复：会话结束时，话题栈随DialogState序列化存入小脑。下次会话启动时，加载历史话题栈并进入三天观察期：检测前三轮对话中是否提及与历史话题相关内容（语义关联度>0.5）。若提及，激活该话题；若未提及，移入沉寂话题区。

定时内容强制激活：若历史话题栈中存在与定时任务关联的话题，在定时触发时强制激活，不受三天观察期限制。

4.2 指代消解

指代检测：丘脑在感知阶段识别代词（“它”“那个”“这个”等），在输出标签中标记contains_pronoun: true。

分层消解流程：

1. 工作记忆消解：遍历当前工作记忆组块，查找最近提及的、与代词匹配的实体。
2. 对话状态消解：查询entity_reference表，按提及轮次和显著性排序，取最匹配的实体。
3. 海马体消解：若前两步均未找到，调用海马体多线索试探检索，从历史事件中查找可能的指代目标。

指代表更新：每轮对话后，将丘脑识别出的实体按提及顺序加入指代表。同名实体的显著性累加。超过10轮未再提及的实体，显著性衰减直至移除。

消解失败处理：生成澄清问题：“你指的是XX还是YY？”用户回应后更新指代表。

4.3 待决问题队列

入队条件：用户提问（意图为“询问事实”或“指令请求”），且前额叶判断需要多轮交互才能完整回答。

状态更新：前额叶每次生成回复后，评估该回复是否解决了队列中某个问题的全部或部分。若完全解决，标记为Resolved；若部分解决，标记为PartiallyAnswered。

语义关联自动清理：

· 每轮对话后，计算当前轮与待决问题的语义关联度（话题向量相似度×实体重合度），追加到semantic_trace。
· 若近100轮累计语义关联度低于阈值（建议0.2），标记为AwaitingCleanup。
· 标记后移入待清理缓存区，保留7天。7天内若语义关联度回升，恢复为Pending；否则永久删除。

用户自主删除：用户可通过指令主动删除待决问题（如“不用管那个问题了”），优先级高于所有自动规则。

定时任务强保留：

· 若待决问题包含定时需求（如“明天提醒我”），标记is_timed=true，解析触发时间戳存入trigger_time。
· 定时任务不受自动清理规则影响，严格按照时间触发。
· 后台定时器到达触发时间时：若用户在线，主动插入提醒；若用户离线，记录待推送通知。
· 最多提醒3次，用户确认后标记为Resolved。

4.4 跨轮推理链维护

推理链记录：当工作记忆组块被压缩为摘要组块时，组块之间的推理关系（前提、结论）作为元数据保留。

推理链回溯：用户追问“为什么”或“怎么得出的”时，根据摘要组块的compressed_ids调回原始组块，按推理关系排序生成解释。

跨会话推理：推理链随任务快照持久化存入小脑，恢复时完整重建。

五、智能生命周期管理流程

```
每轮对话后执行：
1. 更新话题栈，计算话题切换
2. 更新指代表，处理指代消解
3. 对待决问题队列：
   - 计算语义关联度，追加到semantic_trace
   - 检查定时任务：若到达触发时间，触发提醒
   - 检查非定时任务：若近100轮累计关联度 < 阈值，标记AwaitingCleanup
   - 清理：AwaitingCleanup超过7天且未被恢复，永久删除
4. 用户主动删除：立即移除
5. 会话结束时，DialogState序列化存入小脑
```

七、边界情况处理

边界情况 处理策略
指代完全无法消解 生成澄清问题：“你指的是XX还是YY？”
话题栈溢出 底部旧话题持久化至海马体，需要时恢复
跨会话指代 DST向海马体发起时间范围检索
定时任务触发时用户不在线 记录待推送通知，上线后立即提醒
用户修改定时任务 更新trigger_time，重置reminded_count
定时任务关联的话题被用户主动删除 提示用户是否一并取消定时任务
语义关联度记录窗口未满100轮 按实际轮数计算平均关联度
待决问题被标记AwaitingCleanup后用户又提及 恢复为Pending，清空semantic_trace重新累积

九、总结

问题 回答
能否解决多轮对话状态维持？ 能。通过独立的对话状态跟踪器显式维护话题栈、指代表、待决问题队列。
方案是否与现有架构冲突？ 否。DST是对工作记忆、海马体、丘脑已有信息的整合，协同而非替代。
是否支持跨会话恢复？ 支持。对话状态可随任务快照持久化至小脑，下次会话恢复。
是否具备智能生命周期管理？ 是。语义关联自动清理、用户自主删除、定时任务强保留、话题栈观察期。
